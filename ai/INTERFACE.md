# 本地补全接口 v0.1

插件只调用 `POST http://127.0.0.1:18080/v1/chat/completions`。
schema 中可配置端口和 model；主机固定为回环地址、禁用代理与重定向。
不需要 OpenAI 账号或云 API。这只是兼容的 JSON 协议。

请求示例（实际 system prompt 内置于插件）：

```json
{
  "model": "qwen3.5-0.8b",
  "messages": [
    {"role": "system", "content": "只输出紧接前文的短续写，不重复前文、不解释。"},
    {"role": "user", "content": "你好"}
  ],
  "max_tokens": 64,
  "temperature": 0.2,
  "stream": false,
  "chat_template_kwargs": {"enable_thinking": false}
}
```

响应必须是 HTTP 200、UTF-8 JSON：

```json
{"choices":[{"message":{"role":"assistant","content":"，很高兴认识你。"}}]}
```

`content` 只包含新增后缀。插件将当前待上屏文本与后缀拼接为候选，不自动提交。
目前只支持单个短候选、非流式输出，最多 512 UTF-8 字节；响应体最多 32 KiB。
拒绝控制字符、空输出、无效 UTF-8、显式 `<think>` 文本及非 200 响应。
请求文本最多 1024 UTF-8 字节，不会读取剪贴板、已上屏文本或应用全文。

一个进程最多一个请求，不排队；请求运行于独立线程。
连接超时 500ms，发送/单次读取超时 1500ms；读取循环另有 3s 截止检查。
这不是精确的单一总超时：分阶段超时可叠加，但不阻塞按键线程。
编辑、导航、取消或销毁会话会使已有结果失效；候选在请求后 15s 过期。
取消属于逻辑取消，已经到达模型的计算可能继续到完成或 HTTP 超时。

## 日后接入千问 3.5 0.8B

1. 在独立推理进程中加载你的模型/合并后的微调权重。
2. 将兼容服务绑定到 `127.0.0.1:18080`，设置模型别名 `qwen3.5-0.8b`。
3. 关闭思考输出，保证 `message.content` 仅返回补全文本。
4. 停止 mock 服务，启动真实服务；输入法不需要因替换权重重新编译。
5. 用独立数据验证中文续写质量、首字延迟、完整响应延迟、内存与显存占用。

`chat_template_kwargs` 是否生效取决于所用服务，必须在真实接入时核验。
若框架不支持此字段，应在服务配置或适配层关闭思考模式。
当前没有安装/加载模型，没有微调，没有测量真实模型效果或速度。
